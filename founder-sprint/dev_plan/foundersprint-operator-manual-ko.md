# FounderSprint 운영 매뉴얼

## 1. FounderSprint가 무엇인가요?

FounderSprint는 기수(배치) 단위로 창업 프로그램을 운영하는 시스템입니다.
운영자는 기수를 만들고, 사람을 초대하고, 과제·세션·이벤트를 관리할 수 있습니다.
참여자는 초대를 수락한 뒤, 자신에게 해당되는 과제와 일정, 안내를 확인합니다.

쉽게 말하면:
- **기수(Batch)** = 프로그램 한 기수
- **사용자(User)** = 운영자, 멘토, 창업자
- **과제(Assignment)** = 제출해야 하는 일
- **세션(Session)** = 프로그램 일정
- **이벤트(Event)** = 별도 일정, 온라인/오프라인 행사
- **오피스아워(Office Hours)** = 멘토-창업자 일정

대부분의 화면은 **현재 선택된 기수**를 기준으로 보여집니다.

---

## 2. 역할별 차이

### 최고 관리자 (Super Admin)
- 시스템 전체에서 가장 높은 권한입니다.
- 관리자(Admin)가 할 수 있는 모든 일을 할 수 있습니다.
- 다른 사람에게 `Super Admin` 권한도 줄 수 있습니다.

### 운영 관리자 (Admin)
- 기수 운영을 담당합니다.
- 기수 생성/복제, 사용자 초대, 세션/이벤트/과제 관리가 가능합니다.
- 운영 화면에 가장 많이 들어가는 역할입니다.

### 멘토 (Mentor)
- 프로그램 운영에 참여하지만, 기수 자체를 관리하지는 않습니다.
- 과제를 만들거나, 질문에 답하거나, 오피스아워 시간을 열 수 있습니다.

### 창업자 (Founder)
- 기본 참여자입니다.
- 과제를 확인하고 제출할 수 있습니다.
- 질문을 올리거나 오피스아워를 요청할 수 있습니다.

### 공동창업자 (Co-founder)
- 실제 사용 권한은 Founder와 거의 같습니다.
- 다만 등록/초대할 때 어떤 Founder와 연결되는지 지정해야 합니다.

## 3. 기수(Batch) 운영 방법

### 새 기수 만들기
1. **Admin → Batches**로 이동합니다.
2. **Create Batch**를 누릅니다.
3. 기수 이름, 시작일, 종료일을 입력합니다.
4. 저장합니다.

### 기존 기수 구조 복제하기
1. **Admin → Batches**로 이동합니다.
2. 복제할 원본 기수를 찾습니다.
3. **Clone Structure**를 누릅니다.
4. 새 기수 이름과 기간을 입력합니다.
5. **Clone Batch**를 누릅니다.

### 복제할 때 같이 넘어가는 것
- 기수 기본 정보
- 과제 구조
- 세션 구조

### 복제할 때 같이 안 넘어가는 것
- 참여자 목록
- 이벤트
- 오피스아워
- 기존 Google Calendar / Google Meet 링크
- 기존 타겟 설정(회사 지정 등)

즉, **기수 복제는 “운영 틀”만 복사하는 기능**으로 이해하면 됩니다.

### 복제 직후 보이는 버튼
복제가 끝나면 안내 창이 뜨고, 여기서 바로 다음 작업을 이어갈 수 있습니다.
- **Invite Members Now** → 바로 사람 초대하기
- **Review Batch First** → 새 기수 설정 먼저 확인하기
- **Close** → 창 닫기

## 4. 사람 초대하기

### 일반 초대
1. **Admin → Users**로 이동합니다.
2. 초대할 기수를 선택합니다.
3. **Invite User**를 누릅니다.
4. 이메일, 이름(선택), 역할을 입력합니다.
5. 필요한 경우 Founder / Co-founder / 회사 연결 정보를 넣습니다.
6. 저장합니다.

### 여러 명 한 번에 초대
1. **Admin → Users**로 이동합니다.
2. 기수를 선택합니다.
3. 초대 창을 엽니다.
4. **Bulk** 모드를 선택합니다.
5. 이메일 목록을 붙여넣습니다.
6. 역할을 선택합니다.
7. 저장합니다.

### 기수 복제 후 바로 초대하는 경우
기수 복제 후 **Invite Members Now**를 누르면:
- 새 기수가 자동으로 선택된 상태로
- 사용자 초대 창이 열립니다.
- 원본 기수의 활성 멤버가 미리 불러와집니다.

### 미리 불러온 사람 목록 사용 방법
1. 목록을 확인합니다.
2. 초대할 사람만 체크합니다.
3. **Invite Selected Members**를 누릅니다.

### 결과는 어떻게 표시되나요?
화면은 복잡하지 않게 다음 두 가지만 보여줍니다.
- **Invited** = 정상 처리된 사람 수
- **Skipped** = 건너뛴 사람 수

건너뛰는 대표 사례:
- 이미 그 기수에 들어가 있는 경우
- 회사 정보가 충돌하는 경우
- 현재 규칙상 바로 추가되거나 초대가 불가능한 경우

### 기존 사용자 초대 시 주의
모든 초대가 반드시 이메일 발송으로 끝나는 것은 아닙니다.
- 완전히 새로운 사용자는 보통 **초대 이메일**을 받습니다.
- 이미 시스템 안에 있는 사용자는 상황에 따라 **바로 기수 멤버로 추가**될 수도 있습니다.

---

## 5. 초대 수락과 시작 안내

### 사용자가 들어오는 흐름
1. 초대 이메일을 받습니다.
2. 링크를 눌러 로그인합니다.
3. 해당 기수 참여 상태가 활성화됩니다.
4. 시작 안내 메일(온보딩 메일)이 발송될 수 있습니다.

### 시작 안내 메일에 들어가는 것
현재는 아래 링크가 들어갑니다.
- **Assignments**
- **Sessions**
- **Events**

현재 포함되지 않는 것:
- Office Hours

### 링크를 눌렀을 때
링크는 그냥 화면만 여는 것이 아니라,
먼저 **해당 기수를 현재 선택 기수로 맞춘 뒤** 해당 화면으로 이동합니다.

## 6. 과제(Assignments)

### 운영자가 할 수 있는 일
- 과제 만들기
- 제출물 보기
- 피드백 남기기
- 미제출자 확인하기

### 참여자가 할 수 있는 일
- 과제 확인하기
- 제출하기
- 피드백 확인하기

### 24시간 전 리마인더
과제 마감이 다가오면 자동 리마인더를 보낼 수 있습니다.
현재 기준:
- 매시간 검사
- 마감 약 24시간 전 과제만 대상
- **아직 제출하지 않은 사람만** 대상
- 같은 사람에게 중복 발송되지 않도록 기록 관리

---

## 7. 세션(Sessions)과 이벤트(Events)

### 세션(Session)
세션은 기수 안에서 운영되는 일정입니다.
예:
- 강의
- 점검 세션
- 일반 프로그램 일정

특징:
- 기수에 속합니다.
- 필요하면 회사 단위로 대상을 제한할 수 있습니다.
- Google Calendar 일정으로 동기화될 수 있습니다.

### 이벤트(Event)
이벤트는 보다 유연한 일정 항목입니다.
예:
- 온라인 행사
- 오프라인 행사
- 일반 세션형 이벤트
- 오피스아워형 이벤트

특징:
- Google Calendar 연동 가능
- 일부 유형은 Google Meet 링크 생성 가능
- 회사 단위 대상 제한 가능

### 중요한 차이
- **Session은 항상 Meet를 만드는 구조가 아닙니다.**
- **Virtual Event / Office Hour 계열**은 Google Meet 링크를 만들 수 있습니다.

### 복제한 기수에서 주의할 점
복제된 세션은 기존 Google Calendar / Meet 링크를 그대로 가져오지 않습니다.
즉, **일정 구조만 복사되고 외부 연동은 새로 잡아야 합니다.**

---

## 8. 설정(Settings)과 현재 기수 선택

### Settings 화면
사용자는 Settings에서 프로필과 기본 설정을 관리합니다.
여기에는 현재 사용자 정보와 기수 관련 정보가 함께 표시될 수 있습니다.

### 기수 전환(Batch Switcher)
여러 기수에 속한 사용자는 batch switcher로 현재 기수를 바꿀 수 있습니다.
현재 선택된 기수에 따라:
- 보이는 과제
- 보이는 세션
- 보이는 이벤트
가 달라질 수 있습니다.

---

## 9. 오피스아워(Office Hours)

오피스아워는 별도 일정 관리 기능입니다.
기수 복제 후 자동 안내 범위에는 현재 포함되지 않습니다.
즉, 오피스아워는 따로 운영해야 합니다.

## 10. 이번에 실제로 확인된 것

### 확인 완료
- 시스템 빌드가 정상 통과함
- 24시간 리마인더가 실제로 발송됨
- 리마인더가 정확한 시간창(약 24시간 전)만 잡는지 확인함
- 기수 복제 후 안내 창, 사람 초대 연결 흐름이 브라우저에서 정상 동작함
- Company 기준 Virtual Event를 만들었을 때:
  - Google Calendar 일정 생성
  - Google Meet 링크 생성
  - KST 시간 반영
  - 대상자 제한(admin + slit.amazing@gmail.com) 확인
- Company 기준 Session을 만들었을 때:
  - Google Calendar 일정 생성
  - KST 시간 반영
  - 대상자 제한(admin + slit.amazing@gmail.com) 확인

### 아직 완전히 단정하면 안 되는 것
- recipient(받는 사람) 쪽 캘린더에 실제로 어떻게 보이는지
- recipient 메일함에서 모든 메일이 항상 정상적으로 들어오는지
- direct-active 기존 사용자에게 온보딩 메일을 줄지에 대한 제품 정책

즉, **운영자 기준/시스템 기준 검증은 충분히 강하지만, 받는 사람 계정까지 100% 통제해서 본 것은 아님**을 기억해야 합니다.

## 11. 운영 시 꼭 알아둘 점

### 1) 복제는 구조만 복사합니다
사람, 이벤트, Meet 링크까지 다 복사된다고 생각하면 안 됩니다.

### 2) 외부 서비스는 앱 안 성공과 다를 수 있습니다
- Gmail 전송 성공 = 반드시 받은편지함 도착 아님
- Google Calendar 생성 성공 = 받는 사람 캘린더 표시 보장 아님

### 3) 기존 사용자와 신규 사용자는 처리 방식이 다를 수 있습니다
신규 사용자는 초대 메일을 받고,
기존 사용자는 바로 기수 멤버로 들어갈 수 있습니다.

### 4) Session과 Virtual Event는 다릅니다
- Session = 일정 중심
- Virtual Event = Meet 링크까지 포함되는 온라인 행사

## 12. 권장 운영 순서

### 새 기수를 처음 만드는 경우
1. 기수 생성
2. 사용자 초대
3. 과제 / 세션 / 이벤트 확인
4. 필요한 안내 발송

### 기존 기수를 복제하는 경우
1. 기수 구조 복제
2. 과제/세션이 잘 복사됐는지 확인
3. 바로 사람 초대 또는 먼저 검토
4. 회사 대상/범위 설정 다시 확인
5. 세션/이벤트 외부 연동이 필요한 경우 별도 점검

---

## 13. 자주 생길 수 있는 문제와 확인 포인트

### “어떤 사용자가 기수가 안 보인다”
- 그 사용자가 active 상태인지
- 해당 기수에 실제로 들어가 있는지
- 현재 선택 기수가 맞는지 확인

### “초대 메일이 안 간 것 같다”
- 기존 사용자라서 바로 추가된 건 아닌지 확인
- SMTP 설정이 맞는지 확인
- 초대 링크가 생성됐는지 확인

### “Session/Event는 생겼는데 Meet 링크가 없다”
- Event 유형이 Virtual / Office Hour가 맞는지 확인
- Google Calendar 설정이 맞는지 확인
- 복제된 항목인지 확인

### “리마인더가 안 간다”
- 과제가 실제 24시간 전 범위에 들어왔는지
- 이미 제출한 사람은 아닌지
- 중복 방지 기록이 있는지
- cron과 메일 전송이 정상인지 확인
