# FounderSprint 관리자(Admin) 매뉴얼

> 이 문서는 FounderSprint에서 **관리자(Admin) 또는 최고 관리자(Super Admin)** 역할로 프로그램을 운영하는 분을 위한 안내서입니다.

---

## 1. FounderSprint란?

FounderSprint는 **기수(Batch) 단위로 창업 프로그램을 운영**하는 시스템입니다.
관리자는 기수를 만들고, 사람을 초대하고, 과제·세션·이벤트·오피스아워를 운영합니다.

핵심 용어:
- **기수(Batch)** = 프로그램 한 기수 (예: Founder Sprint Batch 6)
- **과제(Assignment)** = 참여자가 제출해야 하는 일
- **세션(Session)** = 프로그램 일정 (강의, 점검 등)
- **이벤트(Event)** = 별도 행사 (온라인/오프라인)
- **오피스아워(Office Hours)** = 멘토/운영진과 창업자 상담 시간

대부분의 운영 화면은 **현재 선택된 기수**를 기준으로 보여집니다.

---

## 2. 역할 구분

| 역할 | 무엇을 할 수 있나요? | 무엇이 안 되나요? |
|------|---------------------|------------------|
| **최고 관리자 (Super Admin)** | 모든 것 + Super Admin 권한 부여 | 없음 |
| **관리자 (Admin)** | 기수/사용자/회사/과제/세션/이벤트/오피스아워 관리 | Super Admin 지정 불가 |
| **멘토 (Mentor)** | 과제 생성, 질문 답변, 피드백, 본인이 host인 오피스아워 요청 응답 | 기수/사용자/회사 관리 불가 |
| **창업자 (Founder)** | 과제 제출, 질문, 오피스아워 요청 | 운영 권한 없음 |
| **공동창업자 (Co-founder)** | Founder와 동일 | 초대 시 Founder 연결 필요 |

## 3. 기수 만들기와 복제

### 새로 만들기
1. **Admin → Batches**로 이동
2. **Create Batch** 클릭
3. 기수 이름, 시작일, 종료일 입력
4. 저장

### 기존 기수 복제하기
이전 기수의 운영 구조를 그대로 가져오고 싶을 때 사용합니다.

1. **Admin → Batches**에서 원본 기수의 **Clone Structure** 클릭
2. 새 기수 이름과 기간 입력
3. **Clone Batch** 클릭

### 복제되는 것
- 과제 구조
- 세션 구조

### 복제되지 않는 것 / 다시 확인해야 하는 것
- 참여자 목록
- 이벤트
- 오피스아워
- Google Calendar / Meet 링크
- 회사별 대상 설정
- 세션의 slides / recording 링크

### 날짜 이동
- 복제된 과제 마감일과 세션 날짜/시간은 **새 기수 시작일 차이만큼 자동 이동**됩니다

### 복제 직후
안내 창이 뜹니다:
- **Invite Members Now** → 바로 사람 초대로 이동
- **Review Batch First** → 새 기수 설정 먼저 확인
- **Close** → 닫기

또한 Batches 화면에서는 **Create / Edit / Clone Structure / Delete**를 관리할 수 있습니다.

## 4. 사용자 관리와 초대

### 한 명씩 초대
1. **Admin → Users**에서 기수 선택
2. **Invite User** 클릭
3. 이메일, 이름, 역할 입력
4. Co-founder의 경우 연결할 Founder 선택
5. 필요하면 회사를 지정
6. 저장

### 여러 명 한 번에 초대
1. **Admin → Users**에서 기수 선택
2. 초대 창 → **Bulk** 모드 선택
3. 이메일 목록 붙여넣기
4. 역할 선택 후 저장

### 복제 후 바로 초대
**Invite Members Now**를 누르면:
- 새 기수가 선택된 상태로 초대 창이 열립니다
- 원본 기수의 활성 멤버를 **source batch**에서 불러와 선택할 수 있습니다
- 원하는 사람만 체크해서 새 기수로 초대할 수 있습니다

### 초대 결과
- **Invited** = 정상 처리된 수
- **Skipped** = 건너뛴 수 또는 실패한 수

### 기존 사용자 vs 신규 사용자
- **신규 사용자** → 초대 메일 + 초대 링크
- **기존 활성 사용자** → 경우에 따라 **바로 기수에 추가**될 수 있음

### Users 화면에서 가능한 추가 작업
- 역할 변경
- 추가 역할(admin / mentor 등) 관리
- 초대 재전송
- 초대 취소
- Dropout 처리 / Restore Batch
- 계정 비활성화(Deactivate) / 재활성화(Reactivate)
- 기수에서 제거(Remove)

### 운영 참고
- Founder는 배치당 최대 수 제한이 있을 수 있습니다
- Co-founder는 Founder 연결이 필요하며, Founder당 수 제한이 있을 수 있습니다
- Users 화면 하단에서 **Recent Audit Entries**와 **Founder Activity**를 확인할 수 있습니다

## 5. 회사 관리와 회사 변경 요청

Founder / Co-founder는 **회사 이탈** 또는 **새 회사 생성 요청**을 보낼 수 있습니다.
관리자는 이를 검토하고 처리합니다.

### 어디서 보나요?
- **Admin → Companies** 화면 상단의 `Pending company requests`

### 무엇을 할 수 있나요?
- 요청 유형 확인
  - `Leave company`
  - `New company`
- 요청자 확인
- 현재 회사 / 요청 회사명 확인
- 승인 / 반려

### 승인하면 무슨 일이 일어나나요?
#### 회사 이탈 요청 승인
- 기존 회사 소속 해제
- 사용자 회사 정보 동기화
- 필요 시 Co-founder → Founder 전환

#### 새 회사 요청 승인
- 새 회사 생성
- 현재 batch에 회사 연결
- 요청자를 해당 회사에 연결
- 승인 결과 알림 생성

### 중요한 예외: Founder가 나가고 Co-founder가 남는 경우
이 경우는 단순 승인하면 안 됩니다.
관리자가 아래 중 하나를 선택해야 합니다.
- Co-founder 1명 승격
- 남은 Co-founder 전원 Founder 전환

### Companies 화면에서 가능한 추가 작업
- 회사 목록 확인
- 회사 생성
- 회사 수정
- 회사 삭제

### Founder / Co-founder의 회사 관리 권한
- 현재 회사에 속한 Founder / Co-founder는 회사 상세 화면에서 `Manage Company`를 눌러 회사 관리 화면에 들어갈 수 있습니다.
- Founder / Co-founder가 수정할 수 있는 항목:
  - 회사 이름 / slug
  - 설명
  - 웹사이트
  - 산업군
  - HQ 위치
  - 설립 연도
  - 회사 로고 / 프로필 이미지
  - 태그
  - 팀 멤버 추가 / 제거
- 관리자 전용으로 유지되는 항목:
  - 회사 삭제
  - Batch assignment 변경
- 즉, 회사 운영자가 회사 프로필을 직접 최신 상태로 유지할 수 있지만, 회사 삭제와 기수 연결 변경은 관리자 권한으로만 처리합니다.

## 6. 초대 수락 후 일어나는 일

### 흐름
1. 사용자가 초대 이메일의 링크를 클릭
2. 로그인
3. 해당 기수 멤버로 활성화
4. **시작 안내 메일(온보딩 메일)** 발송 가능

### 시작 안내 메일에 포함되는 링크
- Assignments (과제)
- Sessions (세션)
- Events (이벤트)

포함되지 않는 것:
- Office Hours (별도 안내 필요)

### 링크 동작
메일의 링크를 누르면 **해당 기수가 자동으로 선택된 상태**로 화면이 열립니다.

### 첫 로그인 후
- 사용자의 프로필 정보가 충분하지 않으면 **Settings** 화면으로 먼저 유도될 수 있습니다

## 7. 과제 관리

### 할 수 있는 일
- 과제 만들기
- 제출물 확인
- 피드백 작성
- 미제출자 확인
- 리마인더 발송
- 과제를 **템플릿으로 저장**해서 재사용
- 특정 회사 대상 과제로 제한

### 과제 템플릿
- 과제를 만든 뒤 **Save as template**로 저장 가능
- 새 과제 만들 때 **Start from template**에서 선택하면 제목, 설명, 템플릿 링크, 리뷰 기준이 자동으로 채워집니다
- 선택한 템플릿은 미리보기로 확인할 수 있습니다
- 불필요한 템플릿은 **Delete** 가능
- 템플릿을 삭제해도 기존 과제는 삭제되지 않습니다

### 과제 상세 화면에서 가능한 것
- 제출물 목록 확인
- 미제출자 확인
- **Send Reminder** 발송
- 피드백/답글 확인

### 수정 제한
- 현재 구현 기준으로 **제출물이 하나라도 생긴 과제는 수정할 수 없습니다**

### 24시간 전 자동 리마인더
- 시스템이 하루 한 번 리마인더 대상을 검사합니다
- 마감 약 24시간 전 과제의 **미제출자**에게 리마인더를 보냅니다
- 같은 사람에게 중복 발송하지 않습니다

## 8. 세션과 이벤트

### 세션(Session)
프로그램 일정입니다. 예: 강의, 점검 미팅

현재 프론트에서는 세션에 대해 아래를 관리할 수 있습니다.
- 생성 / 수정 / 삭제
- **Save as Template**
- **Start from template**
- Slides URL / Recording URL 지정
- 회사 단위 대상 제한
- Google Calendar 일정 동기화

세션은 현재 UI 기준으로 **여러 배치에 동시에 연결**할 수 있습니다.
다만 **회사 단위 대상 제한은 배치를 하나만 선택했을 때만** 사용할 수 있습니다.

### 이벤트(Event)
별도 행사입니다. 예: 데모데이, 네트워킹, 온라인 세미나

현재 프론트에서는 이벤트에 대해 아래를 관리할 수 있습니다.
- 목록 보기 / 캘린더 보기
- 유형 필터
- 여러 배치 동시 노출
- 회사 단위 대상 제한 (배치 1개 선택 시)
- Google Calendar 연동

### 이벤트 유형
- **Virtual**
- **In-person**
- **General Session**
- **Office Hour**

### 세션 vs 이벤트 핵심 차이
- **Session** = 프로그램 일정 중심, Slides/Recording 필드 포함
- **Virtual / Office Hour Event** = Meet 링크 생성 대상이 될 수 있는 행사

### Unified Schedule
- **Schedule** 화면의 날짜 패널에서도 이벤트/오피스아워를 바로 만들 수 있습니다

## 9. 이벤트 / 세션 배치 범위 설정

이벤트와 세션을 만들 때 **어떤 기수에 보이게 할지** 선택할 수 있습니다.

| 선택 | 의미 | 회사 지정 가능? |
|------|------|---------------|
| **All Active Batches** | 현재 진행 중인 활성 기수 전체에 노출 | 불가 |
| **Specific Batches** (1개) | 해당 기수에만 노출 | **가능** |
| **Specific Batches** (2개 이상) | 선택한 기수에만 노출 | 불가 |

즉, **회사 단위 대상 제한은 배치를 하나만 선택했을 때만 가능**합니다.

---

## 10. 오피스아워 운영

오피스아워는 별도 운영 기능입니다.

### 관리자가 할 수 있는 일
- **Schedule Office Hour**
- **Grant Credits**
- 요청 승인 / 반려
- Waitlist 승격
- No-show 표시

### 오피스아워 생성 방식
관리자 UI에서 아래 3가지 방식이 보입니다.
- **Direct Invite - Company**
- **Direct Invite - Founder**
- **Open Office Hour - Batch**

### 창업자 측 화면
창업자는 Office Hours 화면에서:
- Request / Book
- Join Waitlist
- Request Office Hour
를 사용할 수 있습니다.

### 운영 참고
- 오피스아워는 기수 복제 시 자동으로 넘어가지 않습니다
- 시작 안내 메일에도 현재 포함되지 않으므로 별도 안내가 필요합니다

## 11. 설정과 기수 전환

### Settings
프로필과 기본 설정을 관리하는 화면입니다.

### Timezone
- Timezone은 일정 **표시 방식**에 영향을 줍니다
- 다만 모든 생성 폼의 기본 timezone이 완전히 동일하게 동작하지는 않을 수 있으므로, 생성 시 각 폼의 값을 한 번 더 확인하는 것이 안전합니다

### 기수 전환 (Batch Switcher)
여러 기수에 속한 사용자는 **batch switcher**로 현재 기수를 바꿀 수 있습니다.
바꾸면 보이는 과제, 질문, 오피스아워, 스케줄 항목이 달라집니다.

## 12. 운영 시 꼭 알아둘 점

### 1) 복제는 구조만 복사합니다
사람, 이벤트, 오피스아워, Meet 링크는 복사되지 않습니다.

### 2) 복제 후 날짜는 이동하지만 일부 값은 초기화됩니다
- 과제/세션 날짜는 새 기수 시작일 기준으로 이동됩니다
- 세션의 slides / recording, 외부 calendar/meet 정보는 다시 설정해야 합니다

### 3) Gmail/Calendar 성공 ≠ 받는 사람에게 바로 보임
- 메일 전송 성공이 반드시 받은편지함 도착을 뜻하지는 않습니다
- Calendar 생성 성공이 받는 사람 캘린더에 자동으로 뜬다는 보장은 아닙니다

### 4) 기존 사용자와 신규 사용자 처리가 다릅니다
- 신규 → 초대 메일
- 기존 → 바로 추가될 수 있음

### 5) 특정 회사 대상 제한은 화면 노출에 직접 영향이 있습니다
- 과제 / 세션 / 이벤트 / 오피스아워는 특정 회사만 보이게 할 수 있습니다

## 13. 권장 운영 순서

### 새 기수
1. 기수 생성
2. 사용자 초대
3. 회사 / 대상 설정 확인
4. 과제 / 세션 / 이벤트 / 오피스아워 확인
5. 필요한 안내 발송

### 기수 복제
1. Clone Structure
2. 과제/세션 날짜와 내용 확인
3. 사람 초대 (즉시 또는 검토 후)
4. 회사/대상 설정 재확인
5. 외부 연동(Calendar/Meet) 재설정

## 14. 문제 해결

### "사용자가 기수를 못 봅니다"
- active 상태인지 확인
- 해당 기수에 실제로 추가돼 있는지 확인
- 현재 선택 기수가 맞는지 확인

### "초대 메일이 안 간 것 같습니다"
- 기존 사용자라서 바로 추가된 건 아닌지 확인
- Gmail 설정 확인
- 초대 링크 생성 여부 확인

### "Session/Event은 있는데 Meet 링크가 없습니다"
- Event 유형이 Virtual / Office Hour인지 확인
- Google Calendar 설정 확인
- 복제된 항목인지 확인 (복제 시 Meet 복사 안 됨)

### "회사 대상 선택이 비활성화됩니다"
- 세션/이벤트에서 배치를 2개 이상 선택했는지 확인하세요
- 회사 대상 제한은 **배치 1개 선택 시에만** 가능합니다
